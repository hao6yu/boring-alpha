**無料の昼食はない。魔法のバックテストもない。**

BoringAlpha は、システマティック取引研究のための小さく依存の少ない研究室です。その最初の仕事はお金を稼ぐことではありません。最初の仕事は、自分たちを欺きにくくすることです。

最初の戦略 **BA-001 マルチアセット・トレンド** は意図的に単純です。8 つの固定 ETF スリーブは、過去 12 か月のトータルリターンが同期間のキャッシュ・リターンを上回る場合に投資され、そうでなければ現金に留まります。シグナルは月末に観測し、翌セッションの始値で執行します。

> BoringAlpha は研究用ソフトウェアであり、投資助言ではありません。バックテストやペーパートレードが実運用の結果を保証することはありません。リポジトリに同梱のデモ設定は決定論的な合成データを使用しており、経済的な意味を持ちません。

## 現在のマイルストーン

このリポジトリが現在提供するもの:

- ロック済みの BA-001 戦略チャーター
- システムを動かすための決定論的な合成データ
- 将来の実データセットのための厳格なロング形式 CSV 取り込み
- 共通取引カレンダー上の固定スリーブによる月末トレンド・シグナル
- 翌セッション執行と明示的な取引コスト
- 現金利息の計上、取引台帳、エクイティ曲線、リスク指標
- 同じ会計エンジンを使うキャッシュ・ベンチマークと静的等加重ベンチマーク
- 境界を超えたデータを封印する、宣言された評価期間
- 不合理なデータでは実行を停止し、それ以外は記録する合理性チェック
- 事前登録された評価スイープと機械的な昇格判定
- コードの由来自体を記録する、コンテンツアドレス型の不変な実験成果物
- タイミング、ルックアヘッド、コスト、固定スリーブの挙動、決定論を網羅するテスト

税後拡張は、年次の目標エクスポージャー・ベンチマークと 8 つの宣言された税シナリオを追加し、ロット単位のウォッシュセール会計と、アーカイブ済みアカウントのリプレイ時の独立検証を備えます。その NAV 規約と税ポリシーは様式化されたものです。[実装訂正記録](docs/changes/2026-09-04-after-tax-corrections.md) は検証された仕組みと残る限界を述べています。BA-001 の税前分類は **Inconclusive（決定不能）** のままです。完了した [BA-001 税後診断](docs/notes/2026-09-04-BA-001-after-tax.md) は両方のアーカイブ期間を記録します。エクスポージャー一致アロケーションに対する優位は開発期間で維持され、検証期間ではテスト済みのすべての税シナリオで逆転しました。

後継戦略 [BA-002 マルチホライズン・トレンド](docs/strategies/BA-002.md) は、完了済みの[2フィード既見履歴診断](docs/reviews/BA-002-source-sensitivity.md)を持ちます。**修正済みの Yahoo と Tiingo の両入力において実用上の no-go です**。9・12・15 か月のシグナルを、年次 60% 目標ベンチマークに対して合成します。その 5 行スクリーニングは、主要な税後優位が年 50bps 以上、ストレス余裕が正であること、およびコスト控除後ドローダウンが最大 20% で各ペア・ベンチマークを下回らないことを要求します。これらは研究基準であり、リターンや損失の保証ではありません。再利用される履歴ウィンドウは明示的に既見です。通過しても、候補が別途承認されたホールドアウトを申請する資格を得るだけです。[データ・プリフライト](docs/reviews/BA-002-preflight.md) は Yahoo スナップショットに欠落していた TLT 分配金を発見し、新しい Yahoo スナップショットで修正済みです。別途承認されたソース比較は、両既見ウィンドウで 5 つのペア行すべてと 8 つの税シナリオを実行しました。2018〜2021 年、ベース（base）の税後 CAGR は両フィードで約 2.00〜2.03% に対し、ベンチマークは 4.16〜4.21% で、ドローダウンも悪化しています。これらはゲート非関与の診断結果であり、正式な分類や運用エビデンスではありません。元のフリーズは草稿のままです。ホールドアウト評価は承認されず、実行もされていません。

ブローカー接続、実発注、センチメント、押し目のタイミング計り、レバレッジ、機械学習は、このマイルストーンの対象外に意図的に置かれています。

## クイックスタート

Python 3.11 以降が必要です。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
.venv/bin/boring-alpha backtest configs/ba_001_multi_asset_trend.toml
```

このコマンドは `experiments/BA-001/` の下にコンテンツアドレス型の実行ディレクトリを書き込み、戦略/ベンチマークのサマリーを表示します。同じ実行を繰り返すと、黙って上書きするのではなく既存の成果物を検証します。`output_dir` や CSV パスなど設定内の相対パスは設定ファイル自身のディレクトリ基準で解決されるため、作業ディレクトリがどこであっても実行は同じ場所に書き込まれます。

### BA-002 合成データのウォークスルー

リポジトリ外に自己完結したデモを作成し、表示されたコマンドをインストール済みの `boring-alpha` 実行ファイルで実行します:

```bash
ba002_demo_dir=$(mktemp -d)
.venv/bin/python -m boring_alpha.demo "$ba002_demo_dir"
.venv/bin/boring-alpha backtest "$ba002_demo_dir/configs/development.toml"
.venv/bin/boring-alpha sweep "$ba002_demo_dir/configs/development.toml"
.venv/bin/boring-alpha sweep "$ba002_demo_dir/configs/validation.toml"
```

表示された 2 つのスイープ・パスを `boring-alpha classify` に渡します。デモは架空のカレンダーとゼロの分配金を使います。鍛えるのはパイプラインであって、市場パフォーマンスではありません。分配金とロットの仕組みは専用の税テストがカバーします。合成的なフリーズ草稿は作成しますが、確認も実際の実行ジャーナルも作りません。

BA-002 はグリッド行ごとに両アカウント、8 つの税シナリオすべて、独立した想定カレンダー、凍結挙動の契約、フリーズ記録内の完全な人間のチャーター、切り詰められた入力をアーカイブします。公開時にはチェックサム・マニフェストを最後に書きます。分類はアーカイブとアカウントのリプレイを検証し、保存された合格フラグを信用せずにゲートを再計算します。事後の `aftertax` は別個に識別される診断であり、スイープの適格性エビデンスの代用ではありません。

正確には:分類は税前会計をリプレイし、ドローダウンとゲートを再計算します。税後 CAGR と税の整合性チェック結果は、チェックサム付き `tax.json` からの検証済み入力であり、新たに再計算した税務申告ではありません。アーカイブされた意思決定はトレースであり、取引シグナルの独立した再生成ではありません。要求があれば、`aftertax` が別個に識別された税リプレイを提供します。

アーカイブされたフリーズは身元のみの草稿エンベロープであり、決して執行許可ではありません。確認メタデータは追記専用の呼び出しプロビナンスに置かれます。履歴分類はさらに、一致する外部の確認済みフリーズを要求します。合成的な草稿を確認しても、既存の経済成果物は変わらず、実際のジャーナルも初期化されません。

### 正式な履歴研究ワークフロー（未実行）

独立した [NYSE セッション・カレンダー](docs/data/nyse-calendar.md) がリポジトリに収録されました。[ブランチ・レビュー](docs/changes/2026-09-04-branch-review-after-tax-overlay.md) はその後、既見履歴（2006-02-28 から 2021-12-31、3,990 セッション）にわたる SPY の日付のみの完全一致を報告しました。ホールドアウトの市場ファイルは検査していません。後の既見履歴プリフライトで、2 つの履歴設定とフリーズ草稿が追加されました。フリーズは確認せず、正式なスイープも実行していません。その後の[ソース感度実験](docs/reviews/BA-002-source-sensitivity.md) は別個の、分類不能な成果物を使用し、この候補の停止を支持しています。以下の正式ワークフローは文書であり、その結果を受けての BA-002 の推奨次のステップではありません。

チャーターを見直し固定入力スナップショットを選んだら、2 つの場所を設定します（設定ファイル基準で解決）:

```toml
[research]
calendar_path = "../data/calendars/nyse-2006-2026-v1.json"
freeze_path = "../research/ba002-freeze.json"
```

関連するすべての BA-001/BA-002 設定は **同じ正規ファミリー・ジャーナル** を使います: `<Git common directory>/boring-alpha/journals/BA-TREND.json`。インストール済みパッケージのソース・チェックアウトが Git 共通ディレクトリを選ぶため、設定の場所、作業ディレクトリ、リンクされたワークツリーを変えても別の履歴は作れません。実行可能な設定は `research.journal_path` を受け付けなくなりました。Git 管理のソース・チェックアウト外での履歴実行は拒否されます。合成実行はこのジャーナルを探さず初期化もしません。

以下は後日の慎重なレビューのための説明であり、すでに実行されたコマンドでも、ホールドアウトを開く要求でもありません:

```bash
boring-alpha research prepare CONFIG --charter docs/strategies/BA-002.md
boring-alpha research show research/ba002-freeze.json
boring-alpha research confirm CONFIG --hash FULL_DISPLAYED_HASH --reason "Reviewed the complete freeze"
```

`prepare` はチャーター文、挙動、ポリシー、カレンダー、期間、コード/入力の同一性を含む草稿を書きます。市場観測を解析せずにソースバイトをハッシュします。`confirm` は設定された同一性がまだ一致することを確認し、その草稿そのものを確認し、ファミリー・ジャーナルを初期化します。どちらのコマンドも戦略を実行せず、ホールドアウトを明示もしません。既存の草稿は書き込み一回限りです。レビュー済みの改訂には新しいフリーズ・パスを選んでください。

すでに確認済みのフリーズを再確認しても、失われたジャーナルを再作成できません。消去しないでください。バックアップから既存の履歴を復元してください。ジャーナルは Git メタデータ内の永続的なローカル運用状態であり、**`git add` ではコミットされず**、clone/push でも転送されません。別途バックアップしてください。履歴のないクローンを新鮮な科学的ホールドアウトとして扱わないでください。`research/` のレビュー済み非機密フリーズ記録はコミットできます。個人の税入力はローカルに留めるべきです。呼び出しプロビナンスと凍結アーカイブの同一性は別個のままです。

通常の `sweep DEVELOPMENT_CONFIG` と `sweep VALIDATION_CONFIG` は同じ確認済みフリーズを再利用し、実行ごとの承認ファイルはありません。表示されたアーカイブ・パスを `boring-alpha classify DEVELOPMENT_SWEEP VALIDATION_SWEEP --freeze research/ba002-freeze.json` で分類します。合格はホールドアウトを申請する資格でしかありません。最初のホールドアウト実行にはさらに `sweep SEALED_CONFIG --reveal "Explicit reason for this reveal"` が必要です。

ジャーナルは試行、アクセス、失敗、完了を記録します。クラッシュ後は同一の凍結コマンドを再試行します。台帳編集は不要です。すでに明示された被覆範囲でコードを変更した場合は、別途レビューされた新しいフリーズと `--repair-of PRIOR_ATTEMPT_ID --repair-reason "Describe the correction"` が必要です。その修復で許されるのはコード/評価器の変更のみです。候補、ルール、ウィンドウ、ポリシー、カレンダー、入力バイトは一致しなければなりません。修復結果とその再試行は **明示済みデータの診断** であり、新たなホールドアウトや新しい適格性エビデンスには決してなりません。候補を再試行するためにジャーナルを削除・リセットしないでください。管理対象実行はアクセスの **前に** ジャーナル・パスと試行 ID を表示します。重複拒否は `--repair-of` のためのより早い試行を名指しします。

1 つの独立した明示が BA-TREND ファミリーで共有されます。BA-001 の封印期間を明示すると、BA-002 がその履歴を未見と呼べる機会を消費し、その逆も同様です。以後の分析は明示的な既明示データ研究にしかなり得ません。現在の修復コマンドは同一候補のコード/評価器修正を許し、候補をまたぐ診断ワークフローは許しません。履歴の既見ウィンドウは 2022-01-01 より前に終わらなければならず、登録された履歴封印ウィンドウはそこから始まります。

## BA-001 の評価

単一のバックテストは戦略の賛否に関するエビデンスではありません。チャーターは何を併せて実行すべきかを固定し、`sweep` はグリッド全体を一度に実行するため、安定性チェックが事後に選んだ結果のメニューになることはできません:

```bash
boring-alpha sweep configs/my_development_run.toml
```

グリッドは、事前登録された 12 か月ルール、同じルールの倍額コスト版、9 か月と 15 か月の近傍、そして最大寄与スリーブを永久に現金化したルールです。それぞれがチャーターの完全な静的ベンチマークに対して実行されます。スイープは `summary.md`（事前登録結果を先頭に、その後をすべて安定性チェックとして明記）と、C1 から C5 の算術を収めた `criteria.json` を書きます。

併せて、キャッシュとエクスポージャー一致ベンチマーク、片道ターンオーバー、コスト・ドラッグ、最悪月、市場滞在時間、スリーブ別・クラスタ別の寄与分解、静的に対するシャープ差の定常ブロック・ブートストラップ区間を報告します。その区間は点推定に対する正直な対抗手段です。約 10 年分の月次決断ではゼロを含むことが多く、どちらであってもサマリーは平易な言葉でそう述べます。

誤読されやすいので、明記しておくべき 2 つの規約:

- **ターンオーバーは片道です。** 取引ノーショナルは再バランスの両側を合計するため、報告値はその半分です。ポートフォリオの完全な往復は 2 ではなく 1 です。
- **アトリビューションはキャッシュ超過で順位付けします。** スリーブの寄与は、同じ資本が現金に置かれていたなら得られたであろう収益 *より上* の戦略リターンの份额です。これはチャーターの定義であり、C5 が除外スリーブを選ぶのに使うものです。粗利潤は並べて報告します。現金金利が高い時期には、どのスリーブが最も重要かに両者は食い違い得ます。

判定には両期間が必要なため、別のステップです:

```bash
boring-alpha classify experiments/BA-001/sweeps/<development> \
                      experiments/BA-001/sweeps/<validation>
```

`classify` はチャーターの昇格/拒否/決定不能ルールを 2 つのスイープに適用し、基準ごとの算術を表示します。判定は計算されるのであって、書き込まれるのではありません。決定不能は実在する結果です。ツールは別の亜種を誘うのではなく、そう言います。

## 評価期間

すべての実行は対象期間を宣言し、境界は実行設定ではなく `configs/evaluation_periods.toml` に置かれるため、設定は自分のウィンドウを密かに広げられません:

```toml
[evaluation]
period = "development"   # or validation, sealed, exploratory
```

データセットはエンジンが見る前に期間の終わりで切り詰められるため、境界より後のデータがエンジン、指標、データ指紋に到達することはありません。したがって開発実行は、後からデータを追記しても同一性を保ちます。これが `tests/test_seal_identity.py` が固定する性質です。期間外のバックテスト・ウィンドウは拒否されます。アドミッション・ルールはプロファイルが所有します。CLI は明示的な実行ライフサイクルに `open_run` を使い、切り詰めはローダーが担当します。その文脈なしの直接の管理対象履歴ロードは拒否されます。

期間は日付の代わりに `"dataset"` で終われます。BA-001 の封印期間がチャーターの「最新の完全データセット」を表現する方法です。要求された終わりは最新の完全な共有セッションに達しなければならず、より短い選択結果は拒否されます。BA-002 は代わりに固定された正確な契約日を要求します。

BA-001 の `exploratory` モードは、戦略のエビデンスではないという警告を刻印します。同梱の合成デモはこれを使います。保護された履歴アクセスは回避できません。BA-002 は固定ウィンドウに探索エイリアスを受け付けません。

BA-001 はチャーターのレビュー・ゲートを保持します。`validation` 実行は `docs/reviews/<ID>-development*.md` に書かれた開発レビューを要求します。`sealed` 実行はそのレビューと検証レビューの両方に加え、明示的な理由を要求します:

```bash
boring-alpha backtest configs/my_sealed_run.toml --unseal "dev and validation reviewed"
```

理由は実行のプロビナンス記録に記録され、その実行は戦略チャーターの変更ログに列挙されなければなりません。どちらのゲートも暗号学的ではありません。ファイルはいつでも編集でき、`evaluation.periods_path` は別のレジストリを指せます。それらが存在するのは、封印データを見ることが事故ではなく、慎重で見直し可能な行為になるためです。成果物が実際に保証するのは、実行がどの境界に従ったかを宣言することです。解決された期間とその境界は実行同一性の一部であり、境界の違う同じ設定は別の実行です。

2022 年以降の BA-TREND データを露出し得る新しい履歴呼び出し（BA-001 の探索実行を含む）は、観測解析の **前に** 確認済みフリーズと同じファミリー・ジャーナルも要求します。BA-001 の既存の `--unseal` 理由が最初の明示理由も兼ねます。2 番目のフラグは不要です。失敗は明示を保持しますが、同一の凍結再試行または前述の明示的な診断コード修復を許します。管理実行は取得済みの入力バイトを通して使います。これは手続き的な研究保護であり、マシンの所有者に対するセキュリティではありません。読み取り専用のレガシー BA-001 アーカイブ分類に遡及的フリーズは不要です。

BA-001 については、`configs/ba_001_real_csv.example.toml` のオプション research テーブルが 2 つの場所を示します。正確な登録ウィンドウを選び、不変なデータ方法論を一致させたら、`boring-alpha research prepare CONFIG --charter docs/strategies/BA-001.md` で準備し、上のように表示されたハッシュを見直して確認し、BA-001 の既存のレビュー・ファイルと `--unseal` 要件を保持します。これらの指示は BA-001 のホールドアウトの実行を承認しません。古い v1 設定が `data/current` に黙って従って v2 スナップショットへ進んではなりません。一致する凍結スナップショットを明示的に選んでください。

## 実行アーティファクト

各実行は `manifest.json`、`metrics.json`、`decisions.json`、戦略と両ベンチマークのエクイティ/取引 CSV、`provenance.jsonl` を書きます。

`manifest.json` は実験の同一性を記述します。完全な設定テキスト、設定/データ/コードの SHA-256、宣言された期間とその境界、実際にロードされた最初と最後のセッション、シグナルを出さなかった月終を含むすべての警告、任意のデータ品質の発見。一度だけ書かれます。実行識別子は設定/データ/コードのハッシュと解決された評価期間から導かれるため、同一の入力は常に同じディレクトリに着地し、2 回目の実行は成果物を書き直す代わりに検証します。`artifact_schema` のないマニフェストは、スキーマ対応リーダー以前のものです。

取引台帳は約定ノーショナルの傍らに `intended_notional` を記録するため、現金が足りず縮小された注文は部分約定として見えます。また約定価格の傍らに `reference_price` — 決定が下された月末終値 — を記録します。2 つの価格の差がスリッページです。バックテストではオーバーナイト・ギャップであり、ペーパー約定が比較される数値です。

`provenance.jsonl` は呼び出しごとの環境を記述します。タイムスタンプ、Git コミット、作業ツリーが汚れているか、Python バージョン、任意の unseal 理由 — 実行ごとに 1 行ずつ増えます。これらが意図的にマニフェストの外にあるのは理由があります。ドキュメントのみのコミットや Python のパッチ・アップグレードは実験を変えずに環境を変えるため、それらを書き込み一回限りのファイルに折り込むと、無視することを学ぶまで日常業務で整合性チェックが発火し続けるからです。

新しい BA-001 成果物は schema 6 を使い、特定の schema-5/6 互換リーダーを備えます。完全な BA-002 スイープは schema 7 と明示的な戦略/ベンチマーク・アカウント・マップを使います。凍結された実装/評価器ハッシュはそれを消費するコードと一致しなければなりません。将来の挙動変更には、レビュー済みの互換性か元のコード・チェックアウトが必要であり、古いハッシュの自動受入ではありません。

3 つの設定ルールは想定ではなく強制されます。`report.output_dir` と `evaluation.period` は必須であり、`backtest.start` は月の最初のセッションを選ばなければなりません。月の最初の暦日を使ってください。

## 税後評価

設定は `[tax]` テーブルを持ち得ます（様式化された BA-001 ポリシーは `configs/tax_policy.toml`）。持つ場合、スイープの各実行は税前成果物の上の純粋なオーバーレイによって税後も採点されます。約定は実際の株式数に変換され、分配金は自身のロットを開き、売却は宣言された方法でロットを閉じ、ウォッシュセールは調整され、各暦年はキャラクタ保持の繰越の下で課税されます（税後 NAV 規約の下で、税前パスは各年末に支払った税で再スケール）。3 つの入力は既知ではなく宣言されたもの — ロット選択、コモディティ・プールの税上のキャラクタ、株式分配金の優遇比率 — であり、オーバーレイは固定の 8 シナリオ・グリッドで実行され、税後の結論はすべてのシナリオの下で成り立たねばなりません。結果は `criteria.json` の傍らの `tax.json` に、`summary.md` にはサマリー・ブロックが現れます。ドローダウンは税後に再計算されません。

アーカイブ済みスイープは再実行せずに再採点できます:

```bash
boring-alpha aftertax experiments/BA-001/sweeps/<id> --policy configs/tax_policy.toml \
    --distributions data/current/distributions_daily.csv
```

出力はポリシー、分配金、オーバーレイのコード指紋によって名付けられるため、修正されたオーバーレイは別個に識別されるファイルを作り、同一入力は冪等です。同梱ポリシーの税率は連邦のみの様式化シナリオであり、誰かの税率階級ではありません。実税率は未追跡のローカルコピーに置くべきです。

### （任意）キャピタルロス控除の感度分析

8 つのゲーティング・シナリオは、通常所得に対するキャピタルロス控除を除外します。これらのゲートを変えずに明示的な感度分析が利用できます:

```bash
boring-alpha aftertax PATH_TO_ARCHIVED_SWEEP --policy configs/tax_policy.toml \
    --loss-sensitivity configs/loss_sensitivity.example.toml
```

例は **利用可能枠ゼロ** を宣言します。家計の前提を選んだ後にのみローカルコピーを編集してください。年間の未使用控除枠、通常課税所得の外で利用可能であること、および結果の節税がアカウントの外に留まるか明示的に拠出されるかを要求します。税率は推測された個人の税階級ではなく、選択された税ポリシーが既定です。枠は同時に存在する複数アカウントに別々ではなく、一つの税務申告に適用されます。ここでの各戦略/シナリオは代替アカウントであり、加算的な便益ではありません。

この診断はキャピタル・ネッティングの後に短期→長期の繰越を消費し、以後の年と最終清算を再計算します。それを賄った損失を保持したまま税の便益を追加することはありません。外の貯蓄は想定リターンを得ません。拠出モードは様式化された NAV 再スケール実験であり、正確な税ロット資金調達ではなく、自己資金による CAGR/税ドラッグの主張を抑制します。完全なポリシー、アカウント規模、ベースラインと感度の結果は別の `tax-loss-sensitivity-*.json` にアーカイブされます。`tax.json` と適格性は不変です。固定額の控除を含めると、既存の 10 万ドルの研究結果は 2,000〜5,000 ドルに拡大できません。[感度設計](docs/decisions/2026-09-04-capital-loss-sensitivity.md) を参照。

## 実 CSV データ契約

実データ・アダプタは 2 つの CSV を受け付けます。価格はトータルリターン調整済みの始値と終値を使い、分配金と分割が単位を混ぜずにリターン系列に現れます:

```csv
date,symbol,tr_open,tr_close
2024-01-02,SPY,100.12,100.80
```

キャッシュ・データは、前セッションから繰り越されたキャッシュに適用される 1 セッションの成長因子を含みます:

```csv
date,cash_factor
2024-01-02,1.00021
```

日付は銘柄ごとに一意で、値は正でなければなりません。スリーブは異なる日付に始まり得ます。ポートフォリオのカレンダーは、設定されたすべての銘柄にバーがあるセッションであり、最初のそのようなセッションから始まります。その共通の開始の後、欠落バーは実行を停止させるデータ・エラーであり、決して暗黙の現金化ではありません。ダウンロードした市場データと秘密は Git により無視されます。

## データ合理性チェック

ロードされたデータは使用前に検査されます。通常は壊れた系列を意味する発見は実行を停止させます。1 セッションの動きが ±40% 超、始値が前終値から ±25% 超のギャップ、またはキャッシュ因子が −10%〜+30% の外の年率を含意すること — 最後のものは、1 セッション成長因子の場所に利率を入力したときに見えるものです。単に疑わしい発見はマニフェストに記録され表示されます。共通カレンダーの 5 営業日を超えるギャップ、および 10 本以上の同一連続終値。

閾値は実際の危機セッションが通るよう意図的に緩く設定されています。実行のために緩めることもできます:

```toml
[quality]
max_session_return = 0.6
```

検査は評価期間がデータを切り詰めた後に起こるため、発見は実行が実際に使ったデータを記述します。

## ネガティブコントロール

合成データには 2 つのレジームがあり、`[data] regime` で選びます。既定の `trending` はどのトレンド・ルールもよく取引できる遅いサイクルを作ります。仕組みを鍛えるのに有用で、構成上おいしい。`random_walk` はネガティブコントロールです。ドリフトなし、記憶なし、トレンド・ルールが何も稼げずコストを払うべき系列です。両レジームで似て見える結果は、トレンドについてではなく配管（実装の仕組み）についての結果です。
