# BoringAlpha

[English](README.md) | 简体中文 | [日本語](README.ja.md)

> 本文件是 [README.md](README.md)（2026-09-04 版）的简体中文翻译，仅供参考。英文原版为权威版本，可能包含更新的内容。

**天下没有免费的午餐，也没有魔法回测。**

BoringAlpha 是一个用于系统化交易研究的小型、轻依赖实验室。它的首要任务不是赚钱。它的首要任务是让我们难以欺骗自己。

首个策略 **BA-001 多资产趋势** 刻意保持简单：八个固定的 ETF 配置单元（sleeve），当其过去 12 个月总回报超过同期现金回报时投入，否则保留现金。信号在月末观测，于下一交易日开盘执行。

> BoringAlpha 是研究软件，不构成投资建议。回测与模拟交易不保证实盘结果。仓库内置的演示配置使用确定性的合成数据，没有任何经济含义。

## 当前进度

仓库目前提供：

- 已锁定的 BA-001 策略章程；
- 用于驱动系统的确定性合成数据；
- 面向未来真实数据集的严格长表 CSV 接入；
- 共享交易日历上、固定配置单元的月末趋势信号；
- 下一交易日执行与显式交易成本；
- 现金利息计提、交易台账、净值曲线与风险指标；
- 使用同一会计引擎的现金基准与静态等权基准；
- 显式声明的评估期，在边界处封存数据；
- 合理性检查：对不可信数据中止运行，并记录其余发现；
- 预注册的评估 sweep 与机械化的晋级判定；
- 记录代码溯源的内容寻址、不可变实验产物；
- 覆盖时序、前视偏差、成本、固定单元行为与确定性的测试。

税后扩展增加了年度目标敞口基准和八个声明的税务情景，包含批次级的洗售（wash sale）会计处理，并在重放已归档账户时进行独立校验。其净值（NAV）约定与税务政策是程式化的简化设定。[实现勘误记录](docs/changes/2026-09-04-after-tax-corrections.md)描述了经过测试的机制与遗留限制；BA-001 的税前分类仍为**不确定（Inconclusive）**。已完成的 [BA-001 税后诊断](docs/notes/2026-09-04-BA-001-after-tax.md)记录了两个已归档期间：其相对敞口匹配配置的优势在开发期成立，在验证期则于所有受测税务情景下反转。

后继策略 [BA-002 多周期趋势](docs/strategies/BA-002.md)已完成一次[双数据源已见历史诊断](docs/reviews/BA-002-source-sensitivity.md)：**在修正后的雅虎与 Tiingo 两套输入下均为实际意义上的不可行（no-go）**。它将 9、12、15 个月的信号混合，对标年度 60% 目标敞口基准。其五行筛查要求：主要税后优势每年至少 50 个基点、压力边际为正、扣费后回撤至多 20% 且不劣于每一个配对基准。这些是研究判据，不是收益或亏损的保证。复用的历史窗口明确属于已见数据；通过筛查只会使候选策略有资格申请一次单独授权的留存期（holdout）。[数据预检](docs/reviews/BA-002-preflight.md)发现雅虎快照缺失一笔 TLT 分红，现已在新的雅虎快照中修正。单独授权的数据源比较在两个已见窗口中运行了全部五个配对行与八个税务情景。2018–2021 年，基础情形（base）税后 CAGR 在两套数据源下约为 2.00–2.03%，对比基准的 4.16–4.21%，且回撤更差。这些是不设门槛的诊断结果，不是正式分类或部署证据。原始冻结仍为草稿；未授权也未运行任何留存期评估。

券商连接、实盘下单、情绪数据、回调择时、杠杆与机器学习被刻意排除在本里程碑之外。

## 快速开始

需要 Python 3.11 或更新版本。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
.venv/bin/boring-alpha backtest configs/ba_001_multi_asset_trend.toml
```

该命令在 `experiments/BA-001/` 下写入一个内容寻址的运行目录，并打印策略/基准摘要。重复同一运行会校验既有产物，而不是静默覆盖。配置文件内的相对路径（如 `output_dir` 与 CSV 路径）相对于配置文件所在目录解析，因此无论工作目录在哪里，运行都写到同一位置。

### BA-002 合成数据演练

在仓库之外创建一个自包含的演示目录，然后用已安装的 `boring-alpha` 可执行文件运行打印出的命令：

```bash
ba002_demo_dir=$(mktemp -d)
.venv/bin/python -m boring_alpha.demo "$ba002_demo_dir"
.venv/bin/boring-alpha backtest "$ba002_demo_dir/configs/development.toml"
.venv/bin/boring-alpha sweep "$ba002_demo_dir/configs/development.toml"
.venv/bin/boring-alpha sweep "$ba002_demo_dir/configs/validation.toml"
```

将命令打印出的两个 sweep 路径交给 `boring-alpha classify`。演示使用虚构的日历与零分红数据；它演练的是流水线，而不是市场表现。分红与批次机制由专门的税务测试覆盖。它会创建一个合成的冻结草稿，但既没有确认，也没有真实的运行日志。

BA-002 为每个网格行归档两个账户、全部八个税务情景、独立预期日历、冻结行为契约、冻结记录中完整的人类章程，以及截断后的输入。发布时最后写入校验和清单。分类会校验归档并重放账户，然后重新计算各门槛，而不是信任保存的通过标志。事后的 `aftertax` 是单独标识的诊断，不能替代 sweep 的资格证据。

准确地说：分类重放税前会计并重算回撤与门槛。税后 CAGR 与税务一致性检查结果是带校验和的 `tax.json` 中经过验证的输入，不是重新计算的税务申报。归档的决策是痕迹记录，不是对交易信号的独立再生成。需要时由 `aftertax` 提供单独标识的税务重放。

已归档的冻结是仅含身份的草稿信封，永远不是执行许可。确认元数据保存在只追加的调用溯源里；历史分类还额外要求匹配的外部已确认冻结。确认一个合成草稿不会改变其既有经济产物，也不会初始化真实日志。

独立的[纽交所交易日历](docs/data/nyse-calendar.md)现已入库。[分支评审](docs/changes/2026-09-04-branch-review-after-tax-overlay.md)随后报告了与已见历史仅按日期的完全匹配：2006-02-28 至 2021-12-31，共 3,990 个交易日。未检查任何留存期市场文件。其后的已见历史预检新增了两个历史配置和一个冻结草稿。它没有确认冻结，也没有运行正式 sweep。其后的[数据源敏感性实验](docs/reviews/BA-002-source-sensitivity.md)使用了单独的、不可分类的产物，并支持停止该候选。以下正式工作流是文档说明，不是该结果之后 BA-002 的建议下一步。

在评审章程并选定固定输入快照后，配置两个位置（相对于配置文件解析）：

```toml
[research]
calendar_path = "../data/calendars/nyse-2006-2026-v1.json"
freeze_path = "../research/ba002-freeze.json"
```

所有相关的 BA-001/BA-002 配置使用**同一个规范家族日志**：`<Git common directory>/boring-alpha/journals/BA-TREND.json`。已安装包的源码检出决定了 Git 公共目录，因此更改配置位置、工作目录或链接工作树都无法再造另一份历史。可执行配置不再接受 `research.journal_path`。在非 Git 源码检出之外执行历史运行会被拒绝。合成运行不查找也不初始化该日志。

以下是为将来一次慎重评审准备的说明，不是已经运行过的命令，也不是打开留存期的请求：

```bash
boring-alpha research prepare CONFIG --charter docs/strategies/BA-002.md
boring-alpha research show research/ba002-freeze.json
boring-alpha research confirm CONFIG --hash FULL_DISPLAYED_HASH --reason "Reviewed the complete freeze"
```

`prepare` 写入一个草稿，包含章程文本、行为、政策、日历、各期间与代码/输入身份。它对源字节做哈希，不解析市场观测。`confirm` 检查配置的身份仍然匹配，确认那份确切的草稿，并初始化家族日志。两个命令都不运行策略，也不揭示留存期。已有草稿一次写入；修订复核后请选择新的冻结路径。

重新确认一个已确认的冻结无法重建丢失的日志。不要抹掉它：请从备份恢复既有历史。日志是 Git 元数据内持久的本地运行状态，**不会被 `git add` 提交**，也不会随 clone/push 转移。请单独备份；永远不要把没有历史的克隆当作全新的科学留存期。`research/` 中经过评审的非敏感冻结记录可以提交；个人税务输入应保留在本地。调用溯源与冻结归档身份保持分离。

常规的 `sweep DEVELOPMENT_CONFIG` 与 `sweep VALIDATION_CONFIG` 复用同一个已确认冻结，没有按次运行的批准文件。将它们打印的归档路径用 `boring-alpha classify DEVELOPMENT_SWEEP VALIDATION_SWEEP --freeze research/ba002-freeze.json` 分类。通过只意味着有资格申请留存期。首次留存期执行还需要 `sweep SEALED_CONFIG --reveal "Explicit reason for this reveal"`。

日志记录尝试、访问、失败与完成。崩溃之后，重试同一条冻结命令即可；无需编辑账本。在已揭示覆盖面上修改代码，需要单独评审的新冻结与 `--repair-of PRIOR_ATTEMPT_ID --repair-reason "Describe the correction"`。该修复只允许代码/评估器变更：候选、规则、窗口、政策、日历与输入字节必须一致。修复结果及其重试仍属于**已揭示数据诊断**，绝不是新的留存期或新的资格证据。不要为了重试某个候选而删除或重置日志。托管运行会在访问**之前**打印日志路径与尝试 ID；重叠拒绝会为 `--repair-of` 指名较早的尝试。

BA-TREND 家族共享一次独立揭示：揭示 BA-001 的封存期会消耗掉 BA-002 把那段历史当作未见的机会，反之亦然。之后的分析只能是显式的已揭示数据研究。当前的修复命令允许同一候选的代码/评估器修正，不支持跨候选的诊断工作流。历史已见窗口必须结束于 2022-01-01 之前，注册的历史封存窗口从该日开始。

## 评估 BA-001

单个回测不构成支持或反对某个策略的证据。章程固定了必须与它一起运行什么，而 `sweep` 一次运行整个网格，使稳定性检查无法变成事后挑选的结果菜单：

```bash
boring-alpha sweep configs/my_development_run.toml
```

网格是预注册的 12 个月规则、同一规则的双倍成本版、9 与 15 个月的邻近参数，以及将其最大贡献配置单元永久持有为现金的规则。每个都对照章程的完整静态基准运行。sweep 写出 `summary.md`（以预注册结果开头，其后一切标注为稳定性检查）和 `criteria.json`（C1 至 C5 背后的算术）。

同时它还报告现金与敞口匹配基准、单边换手率、成本拖累、最差月份、在场时间、按单元与按簇的归因，以及相对静态基准夏普之差的平稳块自助法（stationary block bootstrap）区间。该区间是点估计的诚实制衡：在约十年的月度决策上它经常包含零；无论哪种情况，summary 都会用直白的语言说明。

两个值得说明的约定，因为都容易被误读：

- **换手率是单边的。** 成交名义本金把每次再平衡的两边都计入，因此报告值是其一半。组合完整进出一次是一，不是二。
- **归因按相对现金的超额排序。** 一个单元的贡献是策略收益中*高于*同额资本闲置现金所得的份额，这是章程的定义，也是 C5 用来挑选移除单元的依据。原始利润并列报告，因为在高现金利率时期，两者可能对哪个单元最重要意见不一。

判定需要两个期间，所以是独立的一步：

```bash
boring-alpha classify experiments/BA-001/sweeps/<development> \
                      experiments/BA-001/sweeps/<validation>
```

`classify` 将章程的晋级/否决/不确定规则应用于两个 sweep，并逐条打印判据算术。判定是算出来的，从来不是填进去的。不确定（Inconclusive）是真实的结果；工具会如实说出，而不是邀请你再造一个变体。

## 评估期

每次运行都声明它针对的期间，边界保存在 `configs/evaluation_periods.toml` 而不是运行配置里，因此配置无法悄悄放宽自己的窗口：

```toml
[evaluation]
period = "development"   # or validation, sealed, exploratory
```

数据集在引擎看到之前就按期间末尾截断，因此边界之后的数据永远不会到达引擎、指标或数据指纹。因此开发运行在追加后续数据后保持其身份，这正是 `tests/test_seal_identity.py` 钉住的性质。评估期之外的回测窗口会被拒绝。准入规则由 profiles 负责；CLI 用 `open_run` 管理显式的运行生命周期，截断由加载器负责。缺少该上下文的直接托管历史加载会被拒绝。

期间可以以 `"dataset"` 而非日期结束，BA-001 的封存期就是这样表达章程的"最新完整数据集"。其请求的结束必须达到最新的完整共享交易日；更短的选择结果会被拒绝。BA-002 则要求固定、精确的契约日期。

BA-001 的 `exploratory` 模式会给运行盖上"不是策略证据"的警告。内置合成演示用的就是它。它不绕过受保护的历史访问；BA-002 不接受为其固定窗口使用探索期别名。

BA-001 保留其章程的评审门槛。`validation` 运行要求 `docs/reviews/<ID>-development*.md` 处有书面开发评审。`sealed` 运行同时要求该评审与验证评审，外加明确理由：

```bash
boring-alpha backtest configs/my_sealed_run.toml --unseal "dev and validation reviewed"
```

理由记录在运行的溯源记录里，且该运行必须列入策略章程的变更日志。两个门槛都不是密码学的：你随时可以编辑文件，`evaluation.periods_path` 也可以指向别的注册表。它们的存在是为了让查看封存数据成为刻意的、可评审的行为，而不是意外。产物真正保证的是：每次运行声明它服从了哪些边界——解析的期间及其边界是运行身份的一部分，因此不同边界下的同一配置是不同的运行。

可能暴露 2022 年以后 BA-TREND 数据的新历史调用（包括 BA-001 的探索运行）也需要在**解析观测之前**持有已确认的冻结与同一家族日志。BA-001 现有的 `--unseal` 理由同时充当其首次揭示理由；不需要第二个标志。失败会保留揭示，但允许完全相同的冻结重试或如前所述的显式诊断代码修复。托管运行全程使用捕获的输入字节。这是程序性的研究保障，不是针对机器所有者的安全机制。只读的 BA-001 旧归档分类不需要追溯冻结。

对 BA-001，`configs/ba_001_real_csv.example.toml` 中的可选 research 表展示了这两个位置。在选定确切的注册窗口并匹配不可变的数据方法之后，用 `boring-alpha research prepare CONFIG --charter docs/strategies/BA-001.md` 准备，如上评审并确认其显示的哈希，然后保留 BA-001 既有的评审文件与 `--unseal` 要求。这些说明不授权运行 BA-001 的留存期。旧的 v1 配置不得静默跟随 `data/current` 进入 v2 快照：请显式选择匹配的冻结快照。

## 运行产物

每次运行写出 `manifest.json`、`metrics.json`、`decisions.json`、策略与两个基准的净值及交易 CSV，以及 `provenance.jsonl`。

`manifest.json` 描述实验的身份：完整配置文本、配置/数据/代码的 SHA-256、声明的期间及其边界、实际加载的首末交易日，以及每一条警告，包括未产生信号的月末与任何数据质量发现。它一次写入。运行标识由配置、数据与代码哈希加解析的评估期推导，因此相同输入总是落在同一目录，第二次运行会校验产物而不是重写。没有 `artifact_schema` 的清单早于具备 schema 意识的读取器。

交易台账在成交名义之外记录 `intended_notional`，因此被可用现金缩小的订单呈现为部分成交；并在成交价旁记录 `reference_price`——做出决策的月末收盘价。两个价格之差就是滑点；回测中它是隔夜跳空，也是模拟成交将要对照的数值。

`provenance.jsonl` 描述每次调用的环境——时间戳、Git 提交、工作树是否脏、Python 版本、任何解封理由——每次运行追加一行。它们刻意放在清单之外：纯文档提交或 Python 补丁升级会改变环境而不改变实验，把它们折进一次写入的文件会让完整性检查在日常工作中频繁误报，直到你学会无视它。

新的 BA-001 产物使用 schema 6，配有特定的 schema-5/6 兼容读取器。完整的 BA-002 sweep 使用 schema 7 与显式的策略/基准账户映射。其冻结的实现/评估器哈希必须与消费它们的代码匹配；未来的行为变更需要经过评审的兼容处理或原始代码检出，而不是自动接受旧哈希。

三条配置规则是被强制执行的，而不是假设：`report.output_dir` 与 `evaluation.period` 为必填，`backtest.start` 必须选中某月的第一个交易日，请使用每月的第一个日历日。

## 税后评估

配置可以携带 `[tax]` 表（程式化的 BA-001 政策见 `configs/tax_policy.toml`）。若携带，sweep 中的每次运行都会在税后另行打分，方式是对税前产物做纯覆盖层（overlay）：成交转换为真实股数，分红开立自己的批次，卖出按指定方法匹配批次，洗售被调整，每个日历年在税后净值约定下以保留所得性质的结转课税（税前路径在每年年末按已缴税款缩放）。三个输入是声明出来的而非已知的——批次选择方法、商品池的税务性质、股票分红的合格（qualified）比例——因此覆盖层运行固定的八情景网格，任何税后结论必须在全部情景下成立。结果写入 `criteria.json` 旁的 `tax.json`，`summary.md` 中有摘要块。税后从不重算回撤。

任何已归档的 sweep 都可以不重跑而重新打分：

```bash
boring-alpha aftertax experiments/BA-001/sweeps/<id> --policy configs/tax_policy.toml \
    --distributions data/current/distributions_daily.csv
```

输出按政策、分红与覆盖层代码指纹命名，因此修正后的覆盖层产生单独标识的文件，相同输入是幂等的。入库政策中的税率是仅联邦的程式化情景，不属于任何人的税级；真实税率应放在不入库的本地副本中。

### 可选：资本损失抵扣敏感性分析

八个门槛情景不包括普通所得的资本损失抵扣。有一个显式的敏感性分析可用，且不改变这些门槛：

```bash
boring-alpha aftertax PATH_TO_ARCHIVED_SWEEP --policy configs/tax_policy.toml \
    --loss-sensitivity configs/loss_sensitivity.example.toml
```

示例声明**零可用额度**；只有在选定家庭税务假设之后，才编辑本地副本。它要求声明每年的未用抵扣额度、其在普通应税所得之外的可用性，以及由此产生的节税是留在账户外还是显式缴入。税率默认取所选税务政策，而不是推断的个人税级。额度属于一份纳税申报，而不是同时各账户单独享有；这里的每个策略/情景都是备选账户，不是可叠加的收益。

该诊断在资本净结转后先消耗短期再消耗长期结转，并重算以后年度与期末清算。它不会在保留用以产生节税的亏损的同时增加税收利益。账户外储蓄不假设有回报；缴入模式是程式化的净值缩放实验，不是精确的税批次出资，并且抑制自融资的 CAGR/税拖累声明。完整政策、账户规模、基线与敏感性结果归档在单独的 `tax-loss-sensitivity-*.json`；`tax.json` 与资格判定不变。一旦计入固定金额的抵扣，现有的 10 万美元研究结果不能缩放到 2,000–5,000 美元。见[敏感性设计](docs/decisions/2026-09-04-capital-loss-sensitivity.md)。

## 真实 CSV 数据契约

真实数据适配器接受两个 CSV 文件。价格使用总回报调整后的开盘与收盘值，使分红与拆股进入回报序列而不混用原始与调整后的单位：

```csv
date,symbol,tr_open,tr_close
2024-01-02,SPY,100.12,100.80
```

现金数据包含应用到上一交易日结转现金的单日增长因子：

```csv
date,cash_factor
2024-01-02,1.00021
```

每个代码的日期必须唯一，数值必须为正。各单元可以在不同日期开始：组合的日历是每个配置代码都有 K 线的交易日，并从第一个这样的交易日开始。在共同开始之后，缺失 K 线是中止运行的数据错误，绝不是隐式转入现金。下载的市场数据与密钥被 Git 忽略。

## 数据合理性检查

数据在使用前先受检。通常意味着序列损坏的发现会中止运行：单日波动超过 ±40%、开盘相对前收盘跳空超过 ±25%，或现金因子隐含的年化利率落在 −10% 到 +30% 之外——最后这种是利率被填进单日增长因子位置的典型样子。仅仅可疑的发现会记录进清单并打印：共享日历中超过五个工作日的缺口，以及十根或更多连续相同的收盘价。

阈值刻意放宽到真实危机交易日能够通过。任何阈值都可以为某次运行放宽：

```toml
[quality]
max_session_return = 0.6
```

检查发生在评估期截断数据之后，因此发现描述的是运行实际使用的数据。

## 阴性对照

合成数据有两种状态，用 `[data] regime` 选择。默认的 `trending` 构造任何趋势规则都能交易良好的慢周期——适合演练机器，而且构造上就讨喜。`random_walk` 是阴性对照：无漂移、无记忆，是趋势规则应当一无所获还要支付成本的序列。在两种状态下看起来相似的结果，是关于管道工程（即实现机制）的结果，不是关于趋势的结果。
