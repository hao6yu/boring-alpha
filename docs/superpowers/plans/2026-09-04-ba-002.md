## Scope and approval

The holder explicitly approved the numerical research criteria:

- Primary worst-scenario after-tax CAGR minus the benchmark's best-scenario
  CAGR is at least **0.005**, or **0.50 percentage point/year**.
- Every stress row retains a strictly positive after-tax margin.
- Every row has pre-tax, cost-net maximum drawdown at most **20%**, and no worse
  than its own benchmark. Each period must pass separately.

These numbers are settled. The rule, tax stylizations, dates and full charter
are still draft. This plan prepares their implementation and synthetic
verification; it is not a lock, an approval record for historical execution,
or permission to reveal any sealed data. Do not turn a synthetic fixture into
a real-data authorization or register proposed dates as already approved.

No new engine, tax-accounting rewrite, parameter search, market-data download,
broker connection or live trading is included. Preserve BA-001's charter,
classification and archived evidence. Preserve the holder's unrelated PNGs.

## Design choices for the implementation

Use small profile-specific extensions, not a second backtesting stack:

- `MultiHorizonTrend` expresses the equal vote; the existing portfolio and
  execution layers continue to implement it.
- A common **15-month readiness requirement** is separate from the active
  horizons. Removing the 15-month vote must not shorten warmup.
- One typed period-evidence record carries the economic inputs and identities
  required by BA-002. Do not feed it only BA-001's pre-tax `variants` map.
- Serialize an explicit row-to-account map for strategy/benchmark pairs.
  Generation and archived replay must use the same mapping.
- Use a BA-002 research-eligibility result, not BA-001's `Advance` enum.
- New BA-002 evidence uses an explicit new schema (proposed schema 7).
  Preserve specific BA-001 schema-5/6 readers; old-schema BA-002 evidence is
  invalid, even if the schema is globally readable.

The machine-readable research contract contains behavior, not mutable prose:
family/candidate, rule, weights, warmup, complete grid, costs, benchmark,
initial capital, data methodology, tax policy/scenarios, criteria, period
bounds/status and calendar identity. Canonicalize and hash it. Archive the
selected human charter separately at freeze. Do not recompute identity from a
live Markdown file that later gains review notes; do not put timestamps,
Git commit or Python version into content identity.

Before real-data eligibility, compare the contract with the independently
approved freeze record, not merely with another sweep's matching contract.
Pure units and synthetic CLI fixtures can use explicitly synthetic contracts;
they cannot satisfy that historical-execution gate.

## Task 1 — signal, decision evidence and config

Files: `domain.py`, `signals/trend.py`, `signals/__init__.py`, `config.py`,
`report.py`; tests in `test_signals.py`, `test_config.py`, `test_report.py`.

1. Add validated horizon inputs and distinct common-warmup semantics for
   BA-002. Keep BA-001 parsing and spec hashes unchanged when new fields are
   absent. Reject duplicate, nonpositive, fractional or boolean horizons.
2. Implement equal votes on each horizon's asset-versus-cash return. Pair
   variants divide by two, not three. No renormalization across active assets.
3. Add an optional structured horizon record: anchor date, per-symbol returns,
   horizon cash return, votes and resulting target. Omit it for legacy records.
   The ensemble must not impersonate one flat return comparison: use explicit
   non-applicability for its old scalar field, with compatible serialization,
   rather than invent an average cash hurdle.

Tests first: hand-constructed 0/1/2/3-vote examples, exact ties, each horizon
using its own cash anchor, partial activation, pair denominators and no signal
before common readiness. Change future prices and require unchanged earlier
votes. Pin next-session execution and BA-001's unchanged decision JSON bytes.
Do not compute expected targets with the implementation's helper.

## Task 2 — pure economic criteria and evidence types

Files: new `period_evidence.py`, `criteria_ba002.py`; `profiles.py`; new
`test_criteria_ba002.py`, existing `test_profiles.py`.

Define an evidence record with all five row definitions, paired pre-tax
metrics, all eight tax scenarios for both accounts, verification results,
window/status and relevant identities. Distinguish invalid evidence (exception,
no financial verdict) from valid evidence that fails an economic gate.

Implement primary `margin >= 0.005`, stress `margin > 0`, and both drawdown
conditions. Interpret the existing signed drawdown metric as a magnitude
explicitly. Aggregate every row, then both periods; never pool their returns.
Use independent worst S / best B, not the minimum of paired differences.

Compare at canonical serialized numeric precision using decimal thresholds
(for example `Decimal(str(value))` after finite/type validation). Do not use
rounded display percentages or a configurable tolerance. In particular, a
floating-point subtraction must not turn a canonical 4.5% versus 4.0% pair
into a failed 50-bps boundary, or let a zero stress margin pass.

Discriminating tests:

- 49.9999 bps primary fails; 50 bps passes. Zero stress margin fails.
- DD 21% versus benchmark 30% fails the absolute cap; DD 19% versus benchmark
  18% fails the relative cap. Exact allowed boundaries pass.
- All matched tax scenarios look favorable, but independent extrema fail.
- Excellent base plus one failed leave-one-out row is not eligible.
- One passing period and one failing period cannot be pooled into eligibility.
- Missing/extra scenarios or rows, non-finite/undefined values, booleans passed
  as numbers, or a failed tax identity in either account are invalid evidence.
- Favorable pre-tax Sharpe cannot override an after-tax failure.

Keep BA-001's C1–C5 and three-way verdict functions intact behind its adapter.
No historical CSV is needed for these tests.

## Task 3 — complete paired sweeps and replay

Files: `profiles.py`, `sweep.py`, `cli.py`, `tax/reconstruct.py`; tests in
`test_profiles.py`, `test_sweep.py`, `test_cli.py`.

1. Build exactly the primary, double-cost and three leave-one-out rows.
   All benchmarks target 60% on the annual schedule; the double-cost pair uses
   20 bps for both accounts. Common readiness applies to all diagnostics too.
2. Dispatch ordinary `backtest` through the profile's primary rule, not the
   currently hard-coded `MultiAssetTrend`. Unknown profiles fail closed.
3. Add the 12-month reference as a non-gating diagnostic, not a sixth variant.
   Preserve cash, full static and exposure-matched diagnostics.
4. Preserve both accounts from each row in the serialized account map. Score
   all of them under the complete tax grid, including stress benchmarks.
   Extend archived replay using that same map; retain legacy flat-name readers.
5. Run independent account reconciliation before fresh-sweep tax scoring as
   well as archived scoring. Do not stamp success without running the check.

Tests first: a synthetic changing-price benchmark whose 10- and 20-bps accounts
actually differ; assert the criterion consumes the correct one. Remove only
a stress benchmark and require failure. Compare direct and archived tax output
account-for-account. Corrupt benchmark equity while tax-local identities would
still pass and require reconciliation to abort. Ensure the diagnostic cannot
be selected as the primary candidate or included in eligibility aggregation.

## Task 4 — independent sessions, exact coverage and warmup

Files: new `data/calendar.py`, `data/loader.py`, `config.py`, profile preflight;
new `test_calendar.py`, existing `test_evaluation.py`, `test_seal_identity.py`.

Use an immutable expected-session artifact with source, version, coverage and
hash metadata, independently sourced for the ETFs' exchange calendars. Include
special closures and half-days as appropriate. Review/archive the real source
before any historical run; provider selection is not resolved by this plan.
Do not write a new holiday algorithm or infer expected dates from prices,
FRED observations or generic weekdays. Synthetic tests use small independently
enumerated calendars with explicitly fictional dates/closure assumptions.

From the first expected evaluation session, derive its preceding month-end
decision and the final expected session of the month 15 months earlier.
Require all necessary history from that earliest anchor through the expected
last evaluation session: every price, cash factor and distribution row must
be complete, with no unexpected priced dates. Validate every active horizon's
anchor and each output curve's exact session sequence. Calendar coverage that
does not reach the required interval is a refusal, not a fallback.

Tests remove the first, last, interior and anchor month-end session from
**every** input at once. All must fail. A declared closure must not be demanded
as a session. Dropping the 15-month vote must not create an earlier first
investment. Keep these coverage requirements profile-specific rather than
retroactively changing BA-001's legacy ragged-start behavior.

## Task 5 — immutable evidence publication and classification

Files: `period_evidence.py`, `report.py`, `sweep.py`, `tax/reconstruct.py`,
`profiles.py`, `cli.py`; report/replay tests and new `test_classify_ba002.py`.

Prepare output bytes first. Publish a completion manifest last, covering
checksums for `criteria.json`, `tax.json`, account mapping, decisions, ledgers,
curves, archived inputs, selected contract and expected-calendar evidence.
Do not create a circular hash: sweep identity derives from frozen inputs/code;
the manifest then checksums result payloads that name that sweep. An incomplete
directory cannot classify. Identical reruns verify bytes; altered ones cannot
overwrite an existing run. Keep volatile provenance separate.

Classification must load verified period evidence and recompute gates; it must
not trust a saved `passed` flag. Verify identities within each sweep and against
the selected contract/evaluator. Between periods, compare strategy/grid/cost
definitions, benchmark, code, tax policy, contract, evaluator and calendar
authority. Market and truncated-distribution hashes can legitimately differ:
verify each against its own manifest, not against the other period's data.

Two artifacts agreeing on an old code hash do not authorize using a changed
evaluator. Require the frozen evaluator identity or explicit compatible
version dispatch. A changed overlay can produce a separately identified
diagnostic; it cannot silently replace locked eligibility evidence.

Tests swap a different sweep's `tax.json`, alter a saved pass flag, remove a
checksum, change only evaluator semantics, or truncate a payload. Require
refusal or recomputation of the true failure. New BA-002 schema requirements
must not be bypassed by labeling the artifact schema 5/6. Re-run the BA-001
golden fixtures through their legacy reader; do not require approval records
that never existed for old archives. Hashes are integrity checks, not proof
against an owner deliberately rewriting every file.

## Task 6 — family-scoped access and attempt records

Files: `evaluation.py`, new small `research_state.py`, `data/loader.py`,
`cli.py`, reviewed registry metadata; new `test_research_state.py` and
`test_evaluation.py`. All tests use temporary synthetic records.

Separate the candidate's frozen execution authorization from the family's
knowledge ledger. Family identity comes from reviewed profile/registry lineage,
not an arbitrary config string. Protect unopened coverage for new invocations
of BA-001, BA-002 and their registered descendants, including exploratory
aliases; changing a strategy ID must not replenish a consumed holdout.
Archived read-only BA-001 classification does not need a retroactive approval.
Resolve profile/family before real input loading; unknown or unregistered
invocations must fail there, not after a differently named rule reads data.

Record each attempted run before execution, including failures without reports.
Before exposing protected observations to computation, require exact scoped
authorization and atomically record access started. Completion records the
artifact; failure/interruption after access conservatively leaves that coverage
revealed. Refusal before access is recorded but does not consume the reveal.
Missing, corrupt or unwritable state refuses access. Concurrent attempts must
not both claim a first reveal; unchanged reproducibility reruns reuse the
original frozen identities and are labeled as reruns.

The current CSV reader parses the full source before truncation. Preserve the
distinction between rows physically present in a snapshot and observations
available for evaluation; bounded seen-period handling must truncate before
signals, metrics and semantic fingerprints. Avoid claiming a cryptographic seal.
For bounded seen-period reads, require date filtering before numeric parsing.
A protected-row numeric-parse trap must never be reached; checking only engine
arrival is insufficient. Also test authorization refusals occur before
protected input loading, including legacy `--unseal` and exploratory entry
points. Raw source provenance hashing does not make those rows evaluated data.

These controls are procedural safeguards, not an access-control system against
the machine's owner. No real approval record or consumed-reveal entry may be
created as a side effect of implementing or testing them.

## Task 7 — reporting, integration and review handoff

Files: profile metadata, `sweep.py`, `cli.py`, `README.md`, synthetic demo
configuration/fixtures and integration tests.

Reports must identify the 9/12/15 rule, each paired benchmark/cost, pre-tax
drawdown and after-tax return conventions, all tax scenarios and each exact
margin. Lead with **seen research A/B**, not independent validation. Use
**eligible to request holdout evaluation** or **not eligible**, never `ADVANCE`
for a seen-history screen. Distinguish invalid/incomplete evidence explicitly.
Remove BA-001-specific “12-month rule”/“C5” wording from BA-002 reports without
changing BA-001's own meaning.

Acceptance is synthetic end-to-end: config → both CLI entry points → complete
sweep → immutable archive → replay → independently recomputed eligibility.
Snapshot differences beyond a selected endpoint must not affect that period's
semantic identity. Docs-only edits must not trigger content-integrity alarms.

Run focused tests after each task and the complete suite at integration:

```bash
.venv/bin/python -m pytest -q
git diff --check
```

Record the actual current executions/subtests, not counts copied from earlier
notes. Demonstrate that deliberate regressions in vote calculation, paired
benchmark selection, extrema selection, calendar completeness and saved-verdict
trust are caught by assertions. Perform these mutations in isolated temporary
copies or controlled test patches; never discard the holder's working edits.

Completion of this plan means code and synthetic evidence are ready for an
independent implementation review. It does **not** mean BA-002 passes research
gates. At handoff, resolve the remaining charter/source choices, record an
explicit freeze and separately scoped seen-history run decision, and only
then prepare historical execution. A holdout reveal still needs its own
explicit decision. No historical commands are part of this plan's test recipe.
