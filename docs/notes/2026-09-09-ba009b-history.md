## Pagination discrepancy caught by validation

Coinbase's [public candle documentation](https://docs.cdp.coinbase.com/api-reference/advanced-trade-api/rest-api/public/get-public-product-candles)
documents `ONE_HOUR` buckets and a maximum `limit` of 350. The initial FCM
probe requested 350-hour intervals with `limit=350`. Each of the first six
perp responses contained exactly 300 candles and omitted approximately the
first two days of the interval. This pattern is evidence of an effective
300-bar ceiling for the tested endpoint, despite the documentation.

The first archive,
`data/us_crypto/futures-history/20260910T000416586815Z/`, is preserved as a
truncation diagnostic and must not be used as the paired historical dataset.
Schema v2 recollects using intervals of at most 300 hours. Requests use
`start=a&end=b-1` for a half-open interval `[a,b)`; no request can require
more than 300 hourly buckets. This recovered 284 additional hours for each
perp, 48 for the BTC dated contract, and 36 for the ETH dated contract.

The collector stores original response bytes before normalization, source
URLs, request/receipt times, HTTP dates, SHA-256 hashes, product identities,
the interval, and collector code hash. Offline loading verifies hashes,
exact requested URLs, FCM/root identity, timestamps, uniqueness, OHLC
consistency, positive finite prices, and nonnegative volume. New collections
always create a new directory; files are opened exclusively.

## Descriptive gaps

Here gap means **dated hourly close minus perp hourly close**, in dollars
per underlying BTC or ETH. Both bars belong to the same bucket, but their
last trades may occur at different moments within that hour. Large apparent
moves may therefore partly reflect asynchronous trading. They must not be
treated as fillable spreads or arbitrage.

| Pair | Gap minimum | Gap median | Gap maximum | Median gap / perp close |
|---|---:|---:|---:|---:|
| BTC | -$35 | $435 | $1,290 | 58.58 bps |
| ETH | -$15 | $10.50 | $30 | 44.39 bps |

For windows requiring a paired positive-volume candle at **every calendar
hour**, the change is exit gap minus entry gap:

| Pair and horizon | Overlapping observations | Minimum change | Median change | Maximum change |
|---|---:|---:|---:|---:|
| BTC, 1 hour | 577 | -$655 | -$5 | $645 |
| BTC, 24 hours | 336 | -$690 | -$15 | $610 |
| ETH, 1 hour | 520 | -$27 | $0 | $25 |
| ETH, 24 hours | 247 | -$26.50 | -$0.50 | $21.50 |

There are no uninterrupted 168-hour paired windows under this strict
calendar criterion. Known scheduled closures can break it too; zero windows
does not itself establish a faulty feed. These statistics overlap heavily,
use no selected entry rule, and exclude funding, fees, margin, slippage,
partial fills, and taxes. They are not strategy returns or independent trials.

## Funding marks and settlement remain separate

The previously archived U.S. CDE portal funding CSVs in
`data/us_crypto/funding-history/2026-09-09-cde-90d/` each have 2,160 hourly
rate observations for BIPZ30 and ETPZ30. Their manifests and importer validate
the hashes, timestamps, and percentage units. Their timestamps overlap all
669 BTC and 619 ETH paired bucket **starts**. A candle beginning at `t`
finishes at `t+1 hour`; its close cannot be used as information available at
`t`. Matching the preceding bucket's end to funding timestamps gives 668 BTC
and 618 ETH paired matches because the newest bucket ends after the last
funding timestamp in that older export. Neither match convention establishes
the exact rate/mark/event alignment used by clearing.

The [CDE funding mechanism](https://help.coinbase.com/en/derivatives/perpetual-style-futures/funding-rate)
uses representative futures and spot marks sampled over the hour, with
VWAP/TWAP and fallback rules, rather than an hourly last trade. It also
distinguishes hourly calculations from later clearing cash adjustments.
The portal CSVs contain rates and annualized rates, not those marks.

[CDE FIX code sets](https://docs.cdp.coinbase.com/derivatives/fix/code-sets)
include funding time, final funding rate, final mark price, and spot mark
price. That establishes relevant fields in the market-data protocol, not
public unauthenticated historical access. This bounded review did not find
an unauthenticated historical series of event-time final marks for the exact
four products. It does not claim that no such dataset exists elsewhere.

The public product metadata contains one current `settlement_price` per
contract. It is not an hourly historical mark series. The exchange's
[settlement methodology](https://www.coinbase.com/derivatives/trading-resources)
uses particular daily settlement windows and fallback rules, while final
expiry settlement uses the specified index. Ordinary candle closes are
therefore only an explicitly labeled proxy for either process. No clearing
cash-flow reconstruction is claimed here.

## Reproduction and interface

```sh
.venv/bin/python -B tools/us_futures_history.py
.venv/bin/python -B tools/us_futures_history.py --snapshot data/us_crypto/futures-history/20260910T000515491884Z
.venv/bin/python -B -m pytest tests/test_us_futures_history.py -q -p no:cacheprovider
```

The first command is a new public collection; the second is offline and does
not overwrite the saved report. All **12 tests pass**. Tests cover the observed
300-bar ceiling, pagination continuity, missing bars, malformed OHLC/volume,
timestamp boundaries, duplicates, exact joining, gap-change sign, zero-volume
exclusion, source URLs, hash tampering, offline replay, and exclusive writes.

```python
from pathlib import Path
from us_futures_history import load_snapshot, paired_rows

snapshot = Path("data/us_crypto/futures-history/20260910T000515491884Z")
manifest, candles_by_id, metadata_by_id = load_snapshot(snapshot)
btc_rows = paired_rows(candles_by_id["BIP-20DEC30-CDE"],
                       candles_by_id["BIT-25SEP26-CDE"])
```

`candles_by_id` contains sorted dictionaries with integer Unix `start` and
numeric `open`, `high`, `low`, `close`, `volume`. Joined rows carry `start`,
`bucket_end`, both closes, gap dollars, gap basis points, and a positive-volume
flag. Add `tools` to the Python import path when importing from elsewhere.
